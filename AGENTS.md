# AGENTS.md — SpecHelper (Excel VSTO Add-in)

Инструкции и антигаллюцинационный кодекс для ИИ-агентов, работающих с проектом `SpecHelper`.
Основаны на **Andrej Karpathy Guidelines** (Think Before Coding, Simplicity First, Surgical Changes, Goal-Driven Execution).

---

## 🛑 АНТИГАЛЛЮЦИНАЦИОННЫЙ КОДЕКС

### 1. Моки ≠ Реальная работа в Excel
- Успешная компиляция `msbuild` или `dotnet build` доказывает отсутствие синтаксических ошибок, но **НЕ доказывает**, что надстройка загрузилась в Microsoft Excel и корректно отработала COM-события.
- Не заявляйте «надстройка работает», пока не проверены реальные вызовы Excel Interop / реестра.

### 2. Запрет на фантомные релизы и обязательный установочный архив
- Ссылки на обновления в `version.json` **ОБЯЗАНЫ** указывать на реально существующие релизы GitHub.
- При каждом релизе в GitHub Releases **ОБЯЗАТЕЛЬНО** загружаются ДВА файла:
  1. `SpecHelper_Setup.zip` — готовый установочный архив для пользователей (включает `Установить.cmd`, `Удалить.cmd`, `bin/`, `databases/`, `Инструкция.txt`).
  2. `SpecHelper_Update.zip` — легковесный архив с DLL для механизма фонового автообновления.
- Релиз публикуется строго через GitHub CLI:
  `gh release create <tag> SpecHelper_Setup.zip SpecHelper_Update.zip --repo pururuall/SpecHelper --title "..." --notes "..."`
  с последующей проверкой статуса: `gh release view <tag>`.
- Пользователи НЕ должны скачивать `Source code (zip)` для установки (так как `bin/` исключен в `.gitignore`).

### 3. Строгий стандарт кодировки: UTF-8 без BOM
- Все файлы конфигурации (`version.json`), манифесты, скрипты (`.ps1`, `.cmd`) и документация сохраняются **СТРОГО в UTF-8**.
- Категорически запрещено допускать появление поврежденного текста («кракозябр» вроде `Р Р°Р±РѕС‡РёР№`) в файлах `.gitignore` и `version.json`.

### 4. Хирургическая чистота репозитория (Surgical Changes)
- Корневая директория должна оставаться чистой:
  - Промежуточные сборки, бинарники и кэши (`bin/`, `obj/`, `packages/`, `.tools/`) исключены в `.gitignore`.
  - Все временные тестовые скрипты и дампы помещаются строго в `.scratch/`.
  - Пакеты обновлений (`SpecHelper_Update.zip`) формируются во временной папке или каталоге сборщика и прикрепляются к GitHub Releases, а не висят неотслеживаемым мусором в корне.

### 5. Безопасность баз данных спецификаций
- Файлы каталогов в `databases/` являются пользовательскими справочниками. Никогда не перезаписывать и не удалять рабочие базы данных без явного подтверждения пользователя.

## 🛠️ ТЕХНИЧЕСКИЙ СТЕК И СТРУКТУРА

* **Язык / Платформа:** C# (.NET Framework 4.8), VSTO (Visual Studio Tools for Office), Microsoft Excel Interop.
* **Каталоги данных:** `databases/` (файлы `.xlsx` со справочниками фурнитуры и материалов).
* **Скрипты установки:** `scripts/` (регистрация надстройки, ключи реестра `HKCU\Software\Microsoft\Office\Excel\Addins\SpecHelper`).
* **Модуль автообновления:** `src/Updater/` (сверка версии через `version.json` на GitHub Releases).
