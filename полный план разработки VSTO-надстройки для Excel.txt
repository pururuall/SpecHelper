# Полный план разработки VSTO-надстройки для Excel 2019 (SpecHelper)
Версия: 2.0 (Доработанный с учетом оптимизации производительности, надежности COM и отказоустойчивости)

---

## 1. Архитектура решения и структура данных

### 1.1. Состав баз данных (вкладки плагина)
Плагин оперирует тремя независимыми справочниками:
1. **Материалы** (листовой прокат, сортовой прокат, трубы, пластики, композиты).
2. **Стандартные изделия / Метизы** (болты, винты, гайки, шайбы, шплинты, подшипники по ГОСТ / DIN / ISO).
3. **Покупные комплектующие** (электроника, приводы, датчики, пневматика, фурнитура).

### 1.2. Схема структуры файлов справочников (.xlsx)
В первой строке каждого файла размещаются обязательные столбцы:
* **`Обозначение`** — артикул, номер ГОСТ/DIN, марка материала или типоразмер (вставляется в активную ячейку `ActiveCell`).
* **`Наименование`** — полное наименование позиции для конструкторской/сметной спецификации (вставляется в смежную ячейку `ActiveCell.Offset[0, 1]`).
* **`Папка`** (или `Категория`) — путь иерархии с произвольной глубиной вложенности через слэш `/`.
  * *Пример:* `Крепеж / Болты / С шестигранной головкой / ГОСТ 7798-70 / Оцинкованные`
  * *Пример:* `Металлопрокат / Листовой / Сталь 09Г2С / Лист г/к`
  * *Пример:* `Пневматика / Фитинги / Цанговые / Прямые`
* *Дополнительные столбцы (опционально):* `Ед. изм.`, `Примечание`, `Поставщик` (не ломают парсер, могут выводиться в таблице для справки).

### 1.3. Хранение и конфигурация путей
* Файлы могут находиться локально или на общем сетевом диске предприятия (SMB).
* Пути настраиваются через диалоговое окно настроек надстройки и сохраняются в:  
  `%AppData%\SpecHelper\config.json`.
* Формат конфигурации:
  ```json
  {
    "MaterialsPath": "C:\\Data\\SpecHelper\\Материалы.xlsx",
    "HardwarePath": "C:\\Data\\SpecHelper\\Метизы.xlsx",
    "ComponentsPath": "C:\\Data\\SpecHelper\\Комплектующие.xlsx",
    "AutoSyncEnabled": true,
    "SyncDebounceMs": 800,
    "SplitterDistance": 240,
    "IsTreeCollapsed": false
  }
  ```

## 2. Движок чтения данных и отказоустойчивость

### 2.1. Чтение данных: отказ от тяжелого DOM в пользу `ExcelDataReader`
* Вместо `ClosedXML` используется легковесный потоковый ридер **`ExcelDataReader`** (плюс `ExcelDataReader.DataSet`).
* **Преимущества:**
  * Читает поток файла на порядки быстрее (50 000 строк загружаются за < 0.3 сек).
  * Не создает объектную модель Excel в памяти (минимальный расход RAM).
  * Открытие потока производится в режиме общего доступа:  
    `new FileStream(path, FileMode.Open, FileAccess.Read, FileShare.ReadWrite)`.

### 2.2. Фоновая автосинхронизация (`FileSystemWatcher` + Debounce + Retry Policy)
* **Debounce (устранение дребезга событий):**
  Excel при сохранении файла генерирует несколько событий `Changed`. Плагин использует таймер задержки (800 мс): чтение запускается только после прекращения потока событий.
* **Retry Policy (перехват блокировки файла):**
  В момент сохранения файл может быть кратковременно заблокирован процессом Excel. Ридер выполняет 3–4 попытки открытия с паузой 250 мс перед генерацией ошибки.
* **Сетевая защита:**
  Для сетевых папок, где `FileSystemWatcher` может терять пакеты уведомлений ОС, предусмотрена кнопка принудительного обновления (`F5` / кнопка 🔄) и опциональный фоновый опрос раз в 10 минут.
* **Потокобезопасность:**
  Фоновое чтение выполняется асинхронно (`Task.Run`). Обновление элементов интерфейса передается в UI-поток через `Control.BeginInvoke` / `SynchronizationContext`.

## 3. Взаимодействие с Excel (COM Interop)

### 3.1. Защита от состояния занятости Excel (Cell Edit Mode)
* Если пользователь дважды кликнул на ячейку листа или редактирует формулу, Excel переходит в модальный режим редактирования, и любой вызов COM завершится ошибкой `0x800AC472 (VBA_E_IGNORE)`.
* **Решение:**
  * Проверка `Application.Ready` / `Application.Interactive`.
  * Перехват `COMException`: если Excel занят, вывод мягкого статус-сообщения в нижнюю панель надстройки: *«Завершите ввод в ячейке (нажмите Enter/Esc), затем повторите вставку»*.

### 3.2. Логика вставки позиции
1. Получение `targetCell = Globals.ThisAddIn.Application.ActiveCell`.
2. Проверка защиты листа (`targetCell.Worksheet.ProtectContents`).
3. Запись `targetCell.Value2 = item.Designation`.
4. Запись `targetCell.Offset[0, 1].Value2 = item.Name`.
5. Автопереход курсора на строку ниже (`targetCell.Offset[1, 0].Select()`) — опционально, настраивается в конфигурации для пакетного заполнения строк спецификации.
6. *Примечание:* Уведомление пользователя о том, что COM-вставка очищает стек `Undo` (стандартное поведение Excel API).

## 4. Эргономика и дизайн интерфейса (Custom Task Pane)

### 4.1. Гибридная панель (`CustomTaskPane`)
* Встраивается в правую часть окна Excel (не перекрывает ячейки, а сдвигает рабочую область).
* Поддерживает режим открепления в плавающее окно (можно вынести на второй монитор). Позиция и размеры сохраняются в `config.json`.

### 4.2. Двухоконная компоновка (`SplitContainer`)
* **Левая область:** `TreeView` (Иерархическое дерево каталогов).
  * Автоматически группирует узлы по цепочке из столбца `Папка`.
  * Клик по промежуточному узлу показывает все элементы ветки (включая дочерние). Клик по конечному узлу — только точные совпадения.
  * Счетчик элементов рядом с названием папки: `Болты ГОСТ 7798-70 (48)`.
* **Разделитель (`Splitter`):** возможность легко менять ширину дерева перетаскиванием мыши.
* **Кнопка сворачивания (`◀` / `▶`):** скрывает дерево папок в ноль, расширяя таблицу результатов на всю ширину панели.

### 4.3. Поиск и фильтрация
* Строка мгновенного поиска (фильтрация «на лету» без задержек).
* Переключатель: `[v] Искать только в выбранной папке` / `[ ] По всей базе`.
* Поиск нечувствителен к регистру и ищет совпадение подстроки как в Обозначении, так и в Наименовании.

### 4.4. Таблица позиций (`DataGridView`)
* Столбцы: `Обозначение`, `Наименование`.
* Двойной клик по строке или нажатие клавиши `Enter` $\rightarrow$ немедленная вставка в лист Excel.
* Подсветка активной строки, поддержка навигации клавишами со стрелками.

## 5. Пошаговый план технической реализации

```mermaid
flowchart TD
    A[Этап 1: Архитектура и модели C#] --> B[Этап 2: Движок чтения ExcelDataReader и Watcher]
    B --> C[Этап 3: UI-контролы UserControl + SplitContainer]
    C --> D[Этап 4: Сервис безопасного COM-взаимодействия]
    D --> E[Этап 5: Сборка VSTO Add-in и интеграция TaskPane/Ribbon]
    E --> F[Этап 6: Тестирование и инсталлятор]
```

### Шаг 1. Каркас проектов и библиотеки
* Создание решения Visual Studio:
  * `SpecHelper.Core` — независимая библиотека логики (чтение, модели, конфигурация, синхронизация, COM-сервис).
  * `SpecHelper.AddIn` — проект VSTO надстройки (CustomTaskPane, лента Ribbon, жизненный цикл надстройки).
* Подключение пакетов: `ExcelDataReader`, `ExcelDataReader.DataSet`, `Newtonsoft.Json`.

### Шаг 2. Разработка ядра данных (`SpecHelper.Core`)
1. Модель `CatalogItem` (`Designation`, `Name`, `FolderPath`, `RawColumns`).
2. Модель дерева `CatalogNode` (`Name`, `FullPath`, `Children`, `Items`).
3. Класс `ExcelCatalogReader`: чтение `.xlsx` через поток со `FileShare.ReadWrite`.
4. Класс `CatalogSyncService`: отслеживание через `FileSystemWatcher` с защитой от дублей (debounce) и механизмом повторных попыток при блокировке.
5. Класс `ExcelInsertionService`: безопасная вставка данных в `ActiveCell` с валидацией состояния Excel.

### Шаг 3. Разработка интерфейса (`SpecHelper.UI`)
1. Контрол `SpecPaneControl` (`TabControl`, `SplitContainer`, `TreeView`, `DataGridView`, панель поиска, индикатор статуса).
2. Диалог `SettingsForm` для назначения путей к файлам баз и параметров автосинхронизации.
3. Логика сворачивания `TreeView` с запоминанием ширины сплиттера.

### Шаг 4. Интеграция с Excel VSTO (`SpecHelper.AddIn`)
1. `ThisAddIn_Startup`: инициализация `CustomTaskPane`, привязка `SpecPaneControl`.
2. Создание XML / Visual Designer Ribbon: кнопка вызова панели, переключатель отображения, кнопка настроек.
3. Регистрация глобального шортката `Ctrl + Shift + B` (через `Application.OnKey`).

### Шаг 5. Тестирование и отладка
1. Создание эталонных тестовых файлов баз:
   * `Материалы.xlsx`
   * `Метизы.xlsx`
   * `Комплектующие.xlsx`
2. Нагрузочное тестирование: проверка чтения файлов с 10 000+ позиций.
3. Тест редактирования базы данных при работающем Excel (проверка фонового автообновления).
4. Проверка поведения при занятом Excel (ввод формулы) и на защищенных листах.

### Шаг 6. Сборка и развертывание
1. **ClickOnce** (для локальной разработки и стандартного развертывания).
2. **Скрипт реестра / Inno Setup** (для надежного развертывания на рабочих ПК без проблем с сертификатами безопасности VSTO):
   * Регистрация надстройки в `HKEY_CURRENT_USER\Software\Microsoft\Office\Excel\Addins\SpecHelperAddIn`.
